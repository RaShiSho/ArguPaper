## Context

The current chat runtime already uses LangGraph and a unified tool layer. The unstable behavior is in the boundary between LLM-generated ReAct actions and concrete tool invocation:

- Tool descriptions do not include exact argument fields.
- Common aliases generated by the model are rejected before tools can run.
- The same failed action can be repeated until `max_steps`.
- Local paper content questions are not deterministically biased toward PaperStore.

## Design

### Local-first routing

`ChatAgentRuntime._planner()` adds deterministic checks before calling the Planner LLM:

- If the user asks to find/filter papers in the local library, create a `list_papers` action with extracted `query` and `limit`.
- If the user asks about the selected/current paper, create a `read_paper_context` action.
- If the user asks about a named paper, create a `select_paper` action first.
- If the user explicitly asks for external search, keep the existing LLM Planner/ReAct path.

The local-first path remains a graph action, not a separate workflow.

### Tool specs and normalization

`ToolRegistry` exposes `tool_specs()` using each registered Pydantic `args_schema`. `LangChainToolbox` exposes this text to the chat ReAct prompt.

Before invocation, `LangChainToolbox.normalize_arguments()` maps common aliases:

- `select_paper`: `query`, `id`, `paper_id`, `name`, `title` -> `paper`
- `read_paper_context`, `analyze_paper`: `id`, `paper`, `name` -> `paper_id`
- `list_papers`, `search_papers`: `keyword`, `keywords`, `name` -> `query`

Normalization is intentionally shallow and exact. It does not perform semantic repair.

### Duplicate-call guard

The chat graph computes a signature from normalized arguments:

`<tool>:<json.dumps(arguments, sort_keys=True, ensure_ascii=False)>`

If the same signature already ran successfully in the current turn, the graph blocks the duplicate and converges to the current observation summary. If the same signature already failed, it blocks the duplicate, appends a warning, and converges instead of consuming another ReAct step.

### Logging

`tool_call` events include normalized arguments. Duplicate blocks emit `duplicate_tool_call_blocked` with the signature and prior outcome.

## Risks

- Heuristic title extraction can miss unusual phrasing. In that case the LLM path remains available.
- Exact duplicate detection will not catch semantically equivalent arguments with different text. This is acceptable for first-stage stabilization.
- `_respond()` still only summarizes observations, so reading local context does not yet produce a full paper explanation. That remains a later responder change.
